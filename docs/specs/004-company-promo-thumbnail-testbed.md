# 회사 홍보 썸네일 자동 생성 테스트베드 명세

> 상태: Implemented
> 작성일: 2026-07-31
> 관련 이슈: [#4](https://github.com/Doyajin174/teguma/issues/4)

## 목표

서로 다른 업종의 회사 3곳을 대상으로, 구조화된 데이터와 재사용 가능한 템플릿에서 1080×1080 홍보 이미지를 재현 가능하게 생성한다.

이 테스트베드는 완성된 MCP 기능이 아니라 다음 제품 가설을 검증하는 수직 프로토타입이다.

> AI가 배경과 카피 계획을 만들고 Teguma가 브랜드 제약을 적용해 편집 가능한 레이어와 최종 이미지를 생성할 수 있는가?

## 테스트 대상

| 회사 | 메시지 | 템플릿 | 검증 포인트 |
|---|---|---|---|
| SEVASA | 충전은 자유롭게, 전력은 똑똑하게 | `split-tech` | 어두운 기술 사진 위 B2B 카피와 피사체 분리 |
| 슈퍼쇼츠 | 블로그 링크 하나로 쇼츠 1분 완성 | `creator-pop` | 밝은 배경, 강한 한글 헤드라인, CTA |
| 주식회사 로드맵 | 도심 속 숨겨진 공간을 깨우다 | `urban-grid` | 스마트시티 사진, 그리드, LiDAR 강조 |

## 입력 계약

입력은 `campaigns.json`의 다음 슬롯으로 구성한다.

```json
{
  "id": "campaign-id",
  "template": "template-id",
  "background": "assets/backgrounds/example.jpg",
  "logo": "assets/logos/example.svg",
  "eyebrow": "짧은 분류",
  "headline": ["첫째 줄", "둘째 줄"],
  "subtitle": "보조 설명",
  "tags": ["태그 1", "태그 2", "태그 3"],
  "footer": "브랜드 보조 문구",
  "palette": {},
  "layout": {
    "textBounds": {},
    "subjectBounds": {},
    "logoBounds": {}
  }
}
```

### 제약

- 캔버스: 1080×1080
- 기본 안전 여백: 56px
- 헤드라인: 정확히 2줄, 각 줄 13자 이하
- 핵심 텍스트: 명시적인 불투명/반투명 underlay 위에 배치
- 텍스트와 `subjectBounds`: 교차 금지
- 회사명·카피·로고: 생성형 배경에 포함 금지

## 출력

각 캠페인은 다음 파일을 생성한다.

- `<id>.svg`: 편집 가능한 벡터 중간 산출물
- `<id>.png`: 1080×1080 최종 이미지
- `contact-sheet.png`: 세 시안 비교판
- `qa-report.json`: 캠페인별 자동 검사 결과

## 렌더링 구조

1. 배경과 로고를 data URI로 SVG에 삽입한다.
2. 템플릿별 그라디언트 underlay와 장식 레이어를 생성한다.
3. OFL 한글 폰트로 카피를 실제 `<text>` 레이어에 그린다.
4. resvg로 SVG를 PNG로 래스터화한다.
5. PNG 헤더를 읽어 최종 해상도를 검증한다.

## 자동 QA

- 모든 선언 영역이 캔버스 안에 있는가
- 헤드라인 영역이 피사체 영역과 겹치지 않는가
- 로고가 피사체와 겹치지 않는가
- 최소 좌측 안전 여백을 지키는가
- 헤드라인 줄 수와 길이 제한을 지키는가
- 핵심 텍스트 대비가 4.5:1 이상이고 큰 강조 글자가 3:1 이상인가
- PNG가 정확히 1080×1080인가

## 의존성 판단

### 채택

- `@resvg/resvg-js`: 정적 SVG의 빠르고 재현 가능한 PNG 렌더링
- `pngjs`: 최종 PNG 해상도 검증

둘 다 테스트베드 전용 devDependency이며 배포되는 MCP 런타임 의존성에는 포함되지 않는다.

### 보류

- Satori: 현재 템플릿은 고정 SVG로 충분하므로 추가하지 않음
- Sharp: 합성 기능은 유용하지만 현재 필요 범위보다 크며 별도 보안 업데이트 추적이 필요함
- PosterLayout/RALF 학습 모델: 현재 데이터 규모에 비해 지나치게 무거움

## 알려진 한계

- 현재 `subjectBounds`는 생성 프롬프트와 시각 검수로 선언하며 자동 검출하지 않는다.
- 카피 줄바꿈은 입력에서 지정하며 의미 기반 자동 줄바꿈은 아직 없다.
- 폰트 글리프 커버리지와 OCR 카피 비교는 수동 검수 단계다.
- 로고를 포함한 결과물의 실제 상업 배포 전에는 각 회사의 승인이 필요하다.
- 생성 배경은 테스트 픽스처이며 실제 캠페인에서는 승인된 사진 자산으로 교체할 수 있어야 한다.

## 완료 기준

- 세 캠페인의 SVG와 PNG가 생성된다.
- 비교판과 QA 리포트가 생성된다.
- 렌더 명령을 다시 실행해 같은 구조의 결과를 만들 수 있다.
- 전체 테스트와 TypeScript 빌드가 통과한다.
