## 워크플로 비교

### 시나리오: "기존 디자인 시스템으로 새 대시보드 화면 만들기"

#### Figma + Claude Design 워크플로

```
1. Figma에서 디자인 시스템 열기
2. Claude Design에 .fig 파일 업로드 시도
   → ❌ 토큰 제한에 걸림, 브랜드 훼손 (P1)
3. 수동으로 스크린샷 + 프롬프트로 브랜드 설명
4. Claude Design이 HTML 생성
   → ⚠️ 전부 비슷하게 생김 (P3)
   → ⚠️ 뷰포트 오버플로 (P4)
5. 결과물을 Figma에 수동 재작업
   → ❌ 라운드트립 불가 (P6)
6. 개발자에게 핸드오프
```

**소요 시간**: ~2-4시간 (반복 포함)
**토큰 소모**: 높음 (전체 HTML/CSS 컨텍스트)
**브랜드 정합성**: 낮음 (수동 프롬프트 의존)

#### teguma + Penpot 워크플로

```
1. AI 에이전트가 get_design_context 호출
   → ✅ 압축된 브랜드 컨텍스트 자동 수신 (P1 해결)
   → ✅ 토큰 1/10로 절감 (P5 해결)
2. get_constraints 호출
   → ✅ MUST/MUST NOT 가드레일 수신 (P4 해결)
3. get_components 호출
   → ✅ 기존 컴포넌트 목록 + 변형 확인
4. AI가 제약 조건 내에서 코드 생성
   → ✅ 브랜드 토큰만 사용 (P3 해결)
5. create_element로 Penpot에 직접 생성
   → ✅ 양방향 (P6 해결)
6. Penpot에서 팀 협업·리뷰
   → ✅ 소스 오브 트루스 유지 (P8 해결)
```

**소요 시간**: ~15-30분
**토큰 소모**: 낮음 (압축 표현)
**브랜드 정합성**: 높음 (토큰 시스템 강제)

## 커뮤니티 증언 vs teguma 해결

| 커뮤니티 불만 | 출처 | teguma 해결 |
|---|---|---|
| "디자인 시스템 업로드했더니 토큰 반 날리고 브랜드 파괴" | HN 48431981 | `get_design_context`가 압축 표현으로 자동 전달 |
| "결과물이 minified CSS 박힌 단일 HTML" | HN 48431981 | 시맨틱 도구로 구조화된 데이터 반환 |
| "전부 비슷하게 생김, LLM boilerplate" | HN 48431981 | 브랜드 토큰 강제 + 색상 역할 추론 |
| "뷰포트 200% 오버플로" | HN 48431981 | `get_constraints`의 MUST NOT 규칙 |
| "토큰 소모가 미쳤고 반복이 느림" | HN 47832366 | 압축 표현으로 컨텍스트 1/10 |
| "Penpot MCP는 되지만 제네릭" | HN 47832366 | 브랜드 컨텍스트 자동 주입 |
